\chapter{引言}

\section{实验背景及意义}

哈希表是一种通过哈希函数把关键字映射到数组相应位置的结构\cite{knuth1973sorting,bender2024sosa}，它在数据库索引、键值存储、编译器符号表以及运行时系统等常见基础架构中被广泛应用。相较于链地址法，开放寻址哈希表将元素直接放置在连续数组中，其查询路径相对较短，缓存局部性表现更优；但是当负载因子上升时，冲突及探测长度会快速影响操作成本。在实际工程操作中，常采用预留空槽的方式以降低冲突发生几率，但这也会致使单位元素所占据的附加空间有所增加。因此哈希表的设计需解决如下具体问题：在确保查询、插入及删除操作时间可有效控制的基础上，如何减少每个元素为实现定位、更新与恢复而额外存储的信息量。

Bender 等人\cite{bender2022otsh}从理论层面阐述了上述问题：在只能花费常数时间执行查询的前提下，若插入和删除允许承担 \(O(k)\) 次元素交换代价\footnote{一次更新过程中被搬移（踢出或回填）的元素个数。}，则每个元素所占的额外空间可从 \(O(\log\log n)\) 比特降至 \(O(\log^{(k)}n)\) 比特\footnote{本文空间开销均按比特计；\(\log^{(k)}n\) 表示对 \(n\) 连续取 \(k\) 次对数。}。该结果表明，开放寻址哈希表的空间利用率不仅取决于空位占比，还与元素搬移、局部引导及键重建信息的编码方式密切相关。此前，紧凑哈希表在常数时间操作下每键约需 \(O(\log\log n)\) 比特冗余；动态检索与 filter 的下界\cite{kuszmaul2024filters}、Iceberg 系列结果\cite{bender2024iceberg,pandey2023iceberght} 以及紧凑检索结构\cite{pagh2008retrieval} 等已逐步逼近信息论下界。本文在该理论框架下开展简化复现与实验验证：具体架构与模块分工见下一节，各模块的算法语义与运作逻辑留待第二、三章展开。

\section{系统结构概要}

为避免后文术语堆砌，本节仅从宏观上勾勒本文实现所采用的分层组织；各模块的算法语义与代码路径不在此赘述。

逻辑上，整张表仍是规模为 \(N\) 的开放寻址结构。实现上按地址将其划分为若干 Facility（表级分区，负责管理本区 Cubby 与 Router），每个 Facility 内包含若干 Cubby（局部存储块，容纳槽位与元数据）及一组 Router（在 Facility 的单个桶内，把键映射到候选 Cubby 与槽位）。元素最终落在 Cubby 的槽位上：槽位只保存经商压缩剥离寻址低位后的载荷比特，恢复完整键所需的变长信息由 MiniArray 另行打包存放。插入与删除在 Cubby 内沿 k-kick 规则做有界搬移；表规模变化时通过 active/old 双表在后续操作中按预算逐步迁移，避免一次性全表重哈希。

可将上述名称理解为“分区—局部块—槽位”的三级骨架，以及配套的局部定位、压缩存储与渐进扩缩容手段；后文直接使用这些术语，不再逐条给出形式化定义。

\section{国内外现状}

哈希表实现主要包括链地址法与开放寻址法两大类\cite{knuth1973sorting,bender2024sosa}。链地址法借助链表或桶结构处理冲突，实现直接，但指针与动态分配会带来额外空间和缓存开销。开放寻址法将元素置于数组槽位，局部性较好，却易受负载因子、探针序列与删除策略影响。布谷鸟哈希\cite{pagh2004cuckoo,lehmann2023sichash}以多候选位置与踢出过程缩短查询路径；最小完美哈希\cite{lehmann2026mphsurvey,lehmann2024shockhash,hermann2024phobic}面向静态集合提供更强查找保证，其动态扩展与紧凑编码亦有持续研究\cite{kuszmaul2024filters,lehmann2025combined}；打包与压缩哈希表\cite{kurpicz2023pachash}、IcebergHT\cite{pandey2023iceberght,bender2024iceberg} 等工程方案则侧重实际吞吐与空间折中。这些路线分别改进了查询确定性、构造效率或空间利用率，但在“动态插入删除”与“极低附加比特”之间仍难以同时兼顾。

近年来，研究进一步聚焦到位级空间开销：仅靠负载因子无法刻画紧凑哈希表的真实成本，因为系统还须保存支持查询、更新与键恢复的辅助结构。Bender 等人的最优时间/空间权衡框架\cite{bender2022otsh}将元素放置建模为带删除的球槽分配\cite{aamand2021dynamic,bansal2022deletions}，并以 k-kick 树、局部查询路由器（Local Query Router）、MiniArray 与商压缩组合出可调的权衡曲线。本文工作定位于该框架的工程化简化与实验观察：复现可落地的核心结构，记录简化设计与严格理论模型之间的差异及其对结论适用范围的影响。

\section{实验路线}

本文以 Bender 等人\cite{bender2022otsh}的关键构造为核心，进行简化复刻与实验评估。实现沿用 Facility--Cubby--Slot 组织：Facility 维护 Router 并完成地址分区，Router 给出候选 Cubby 与槽位，槽位存放商压缩载荷，MiniArray 保存键恢复所需的变长元数据，扩缩容采用 active/old 双表渐进迁移。实验重点覆盖插入、查询、删除、键恢复与迁移路径，并统计踢出次数、Router 访问步数、元数据位数等指标。

本文针对三个相互联系的问题依次展开论述：
\begin{enumerate}
  \item 当前实现能否稳定完成批量插入、命中查询与删除等基本操作。
  \item 插入搬移次数、Router 步数与逻辑元数据位数在实际运行中呈现何种规律。
  \item 相对原论文框架做了哪些简化，这些简化如何限制实验结论的外推范围。
\end{enumerate}
