\chapter{总结与展望}
\label{ch:concl}

\section{工作总结}

本文以 Bender 等人提出的最优时间/空间权衡框架\cite{bender2022otsh}为理论基础，完成了分层哈希表的结构与算法设计，并据此实现简化系统、开展性能实验。系统设计与实验过程中，困难点在于将论文中不同的模块的理论模型落地实现，并将不同的模块进行组合，形成一个完整的系统，同时各参数的取值需要进行实验验证，以保证系统能够正常运行。

在设计层面，第二、三章给出了 Facility--Cubby--Slot 分层组织、 MiniArray、Cubby 内部的 k-kick 树、Local Query Router 与商压缩等模块的完整方案。MiniArray 用 B 树与 Rank/Select 维护变长元数据；k-kick 逻辑上在不同 bins 之间以有限次交换完成插入；Local Query Router 通过前缀树将查询映射到目标槽位；各模块经 storage、MiniArray $B$、MiniArray $M$ 与 Local Query Router 的同步更新保持一致性。

在实验层面，第四章在 \(K=\log^3 n\)、\(k=4\)、\(c=2\) 等基准配置下完成 \(n\)、\(K\)、\(k\) 及 Cubby 重构四组测量：\(n\) 从 \(10^3\) 增至 \(10^5\) 时查询延迟由 2.8\,$\mu$s 升至 6.1\,$\mu$s，增删与 rebuild 随规模上升而更活跃；纯插入与纯删除 workload 分别体现 rebuild\_up 与 rebuild\_down 主导；kick 深度增大时 insert\_moved\_max 不超过 \(k\)，与第二章交换上界一致。

综上，本文完成了从理论结构到可运行原型的设计与实现，明确了工程简化相对严格模型的差异界限，为相关研究提供了实验数据与参考。

\section{不足与局限}

受时间与实验条件限制，本文仍存在以下不足：
\begin{itemize}
  \item 未与 IcebergHT\cite{pandey2023iceberght}、PaCHash\cite{kurpicz2023pachash} 等同类系统进行同机对比，尚难从相对角度评价本原型的工程竞争力；
  \item 插入与删除延迟显著高于查询（如 \(n=10^5\) 时分别为 51.2\,$\mu$s、197.3\,$\mu$s 对比 6.1\,$\mu$s），与 MiniArray 维护、k-kick 踢出及 tier 重构等热路径实现相关，仍有优化空间；
  \item 实验 workload 以键均匀分布的混合增删为主，对键偏斜、超大规模长跑及 active/old 双表渐进迁移等场景覆盖不足，结论外推范围仍受测量口径限制。
\end{itemize}

\section{展望}

后续工作可从以下几方面展开：在更大规模与偏斜负载下观察 tier 重建与双表迁移对尾延迟的影响；对插入、删除热路径做针对性优化；选取一至两个紧凑哈希开源实现进行同机对比；补充进程级内存与吞吐的端到端测量，更全面地评估空间--时间权衡\cite{kurpicz2023pachash,lehmann2026mphsurvey}。
